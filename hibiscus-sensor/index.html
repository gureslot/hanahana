ハイビスカス点滅センサー

ハナハナのハイビスカスの点滅をカメラで認識します。

0
点滅
形花の赤色の違い葉の緑速さ
調整
使い方
  • ボーナス中に点滅しているランプを、色付きの枠にぴったり合わせて映します。
  • 左右どちらのランプを映すかを、左下で選びます。
  • 5つの判定が緑に揃うとゲージが緑になり、点滅を数え始めます。
  • 枠がランプに合わないときは「調整」→「枠を動かす」で、枠をドラッグして移動、右下の丸でサイズを変えます。外枠は部位全体、破線の内枠は色が確実に出る中心部に合わせます。
  • 判定が揃わないときは、赤いままの判定のしきい値をスライダーで動かします。カメラの下に出る数値が目安です。
  • 調整した内容はこの端末に保存されます。「設定値をコピー」で書き出せます。
仕組み

映像を320×240に縮小し、0.05秒ごとに枠の中の色と明るさを測ります。毎回、次の5つを全部満たしているかを見ます。

  • 形：枠の内側が、枠の外（背景）より十分に明るい
  • 花の赤：花びらの枠の色相が赤〜橙
  • 色の違い：花びらとめしべが別の色（赤と黄）
  • 葉の緑：左右の葉の枠が、どちらも赤ではない
  • 速さ：明るさの変化が1秒に5.5〜12回

直近20回のうち6割以上が合格すると「ロック」になり、そこから花びらが明るくなって暗くなるたびに1点滅と数えます。

枠は2重です。太い外枠は部位をまるごと包む範囲で、形の判定に使います。破線の内枠はその部位の色が確実に出る範囲で、色の判定に使います。

つまずいた所とコツ
  • 一瞬の色で判定すると揺れる。点滅は半分が消灯しているので、1コマずつ判定すると点滅に合わせて合否が行ったり来たりしました。直近の合格率でロックする形にして落ち着きました。
  • 勘で調整するより、測ってから決める。判定を書いて実機で外れて数字をいじる、の繰り返しは収束しませんでした。判定なしで生の数値を記録するモードを作り、本物とMAX BETランプなどを撮り比べて、2つを分ける境目を逆算する方法に変えてから決まりました。
  • 明るさの絶対値は当てにならない。ホールごとに照明が違うので、「何以上」という明るさの基準は場所で崩れます。色相や、枠の内と外の差のような相対的な値で見ています。
  • 点滅の速さだけでは弱い。本物は約7回/秒、MAX BETは約3回/秒ではっきり分かれますが、一定のリズムで手を振っても似た速さは出せます。色と形を主役にして、速さは補助に回しています。
  • 露出を下げると形が取れる。カメラの露出を下げると、黒い背景に赤い花・緑の葉・黄色いめしべがくっきり浮きます。起動時に自動で下げています（下げられない機種もあります）。
  • 枠は大きすぎると色が薄まる。めしべの枠を大きく取っていたときは、背景が混ざって黄色が出ませんでした。2重枠にしたのはこのためです。
  • めしべだけの点滅は拾えない。画面の一部しか光らないので、全体の変化に埋もれます。対象はボーナス中の全体点滅に絞りました。
  • 光った瞬間に反応させない。明るくなっただけで数えると何にでも反応します。数秒かけてパターンを確かめてから数え始める形にしています。

赤・緑・黄の配置と点滅の速さを合わせて見ているので、同じ赤いハイビスカスでも沖ドキのランプには反応しません。

ゲームに組み込む

判定部分だけを1つの関数にまとめています。下のコードをコピーし、video要素を渡すだけで動きます。

const sensor = createHibiscusSensor(document.querySelector('video'), {
  side: 'L',                        // 'L'=左ランプ / 'R'=右ランプ
  // 「調整」の「設定値をコピー」の内容（tune: … boxes: …）をここに貼ると反映。省略時は初期値
  onBlink() { /* 点滅1回ごと（ロック中のみ） */ },
  onFrame(s) { /* s.locked, s.rate, s.checks, s.hz など */ },
});
sensor.start();   // カメラ起動（ボタンを押したときに呼ぶ）
// sensor.stop();  sensor.setSide('R');  sensor.tune.LOCK_RATE = 0.7;
