# canon-00-index — チカリアン canon の入口・地図【最初に読む】

> これは「チカリアン」設計の**唯一の正（canon）**セットの入口。各ドメイン＝1ファイル。迷ったらここで行き先を引く。
> **1ドメイン＝1ファイル**。同じ話は1か所だけに書く。重複・矛盾を見つけたら canon を直す。

## 使い方
1. 探している話題を **§逆引き** で引く → 該当 canon を開く。
2. 各 canon は **本文（設計者向け）＋▼実装（式・キー）** の2層。ふだんは本文だけ読めばよい。
3. 「実装が今どうなっているか／設計とのズレ」は **canon-07** に集約。

## 書き方の原則（重要）
- **意図とゲームの運びを先に、数値は後**。各項はまず「**何のために・どう遊ばせたいか・ゲームがどう進むか（運び）**」を本文で固める。**具体的な数値は ▼実装 に置き、原則【仮】＝調整対象／要シミュ**として扱う。
- **数値を先に決めない**（数値先行は破綻しやすく、シミュのたびに全部が揺れてごちゃつく）。先に確定するのは **意図・運び・制約**。数値はそれを満たすよう後から（多くはシミュで）詰める。
- ある数値の「唯一の置き場」を1か所に決め、他からは参照する（同じ数値を各所に再掲しない＝ひとり歩き防止）。

## 凡例（全 canon 共通）
- **【確定】**＝動かさない。
- **【仮】**＝調整対象（効果量・倍率・コスト等の暫定値）。
- **【暫定】**＝シミュ依存・要再検証（主にボス曲線）。
- **【要追従】**＝設計は確定だが repo 実装が旧＝更新が必要（一覧は canon-07 §3）。
- **【未実装】**＝SQL未起票（canon-07 §4）。

## 優先順位（どれが正か）
- **設計の正＝最新チャット決定 ＞ 新しい md ＞ 古い md**（決定済みの設計値）。
- **未決定・挙動・メカニクスの正＝実装（repo）**。
- repo は調整中で**遅れている**。stale な SQL の旧値で**確定済みの設計値を上書きしない**（旧値は canon-07 §3「要追従」に記録）。
- **repo が常に正の実体**：`C:\Users\justi\projects\hanahana\Chikarian`（GitHub Pages: gureslot/hanahana）。チャット添付ではなく repo か Claude Code に読ませる。

## 絶対固定（動かさない）
- **デッキ＝3枚**（唯一の絶対固定）。
- それ以外は全て調整前提。クリア目標は **約30〜40日**（旧「90日で8面」は破棄）。

## 設計原則（外さない方針）
- **全レアが戦力**：N/R/SR/SSR は最後まで戦力として使う（特定レアだけで固める設計にしない）。これは**デッキコスト上限11**（SSR5/SR3/R2/N1）が担保＝SSRは3枚積めず・2枚でも3枚目はN限定なので、**どの編成も下位レアを含む**。よって全レアの育成・★価値が一貫して続く（canon-02 §5・canon-04 §8）。
